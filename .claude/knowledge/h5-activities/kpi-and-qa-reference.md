# KPI 選單、標準 Data Request 模板與跨地區/QA 檢查清單

## KPI 完整選單

日常溝通用「參與率、完成率」就夠了；使用者需要正式 Data Request 或深度覆盤時，套用以下 9 項（多份不同活動工單的 Data Request 段落幾乎一字不差，代表這是公司標準模板，不是個案，可直接照抄結構）：

1. Visitor rate 曝光後進站率
2. Participation rate 參與率
3. Completion rate 完成率
4. Return rate 回訪率（R2~R14 登入率，比參與率更嚴謹的活躍指標）
5. Share rate 分享率
6. Invite rate 邀請發出率
7. Collection rate 邀請配對成功率
8. High score achieve rate 最高分/里程碑達成率
9. Open rate 平均開啟次數

常見簡化版（多份工單重複出現的說法）：活動點擊率（拆「拍臉圖」vs「活動中心」兩種入口）、每日點擊率、活動參與率（判定＝進小遊戲或領任務獎勵）、各任務每日完成率、各小遊戲每日/歷史人均參與次數、玩家平均參與總天數、玩家平均代幣獲取數、各級獎勵達成率。

## 跨地區／合規／QA 檢查清單

- **法規彈窗**：TH 等地區法規要求個資同意彈窗，選 Accept 或 Decline 都要放行、不能卡關，只需記錄結果。
- **在地化不只是翻譯**：色票、字體（含「手寫感」字體選擇）、分享文案、社群 icon 都要按地區分開規範。
- **效能與裝置基準**：LCP < 4s、FID < 100ms、CLS = 0，裝置矩陣 Android/iOS/iPad。
- **三階段環境驗收**：testing → formal → live，逐級把關。
- **需求定義階段就列出灰色地帶**：規則模糊處要主動列成問題清單附在點子後面，不要自己假設答案帶過。

## 其他通用 UI 細節提醒

- 教學：首次進入要有強教學遮罩（3張圖以內），機制彈窗要有二次確認（尤其消耗遊玩次數或影響進度的操作）
- 排行榜：設計「未上榜」與「已上榜」兩種狀態，同分時通常上榜時間早的排前面
- 里程碑類：設計完整四態視覺（未達標鎖住／已達標未到開放時間／已到時間未達標／已領取）
- 高併發發獎：走遊戲內信箱＋公告「預計24小時內發放完畢」
- 最終驗收要對照活動當初設定的 Expected Result，不是只看活動本身好不好玩
